# Измерение существующего сетевого пути

`scripts/benchmark-network.py` не подключает VPN и не меняет маршруты. Заранее подготовьте доступный iperf3 server и отдельный TCP endpoint для замера времени установки соединения. Установите Python 3 и iperf3 на клиенте; версия iperf3 на сервере должна быть совместима. Убедитесь самостоятельно, что трафик идёт по нужному пути, и что сервер разрешает измерения.

Пример PowerShell (замените адреса и порты на свои):

```powershell
python scripts/benchmark-network.py --label baseline --host 192.0.2.10 --port 5201 --latency-host 192.0.2.10 --latency-port 443 --output baseline.json
python scripts/benchmark-network.py --label tunnel --host 192.0.2.10 --port 5201 --latency-host 192.0.2.10 --latency-port 443 --output tunnel.json
```

Метка записывается в отчёт и не управляет VPN: переключите путь самостоятельно между запусками. Используйте одинаковые endpoints, параметры и условия; повторите измерения в обе стороны (`--reverse`), в разное время и на реальных сетях. `--udp-bitrate 10M` задаёт предлагаемую нагрузку UDP, а не достигнутую скорость. Потери и jitter берутся из JSON iperf3; jitter не является задержкой. При высокой нагрузке или ограничениях сервера сравнение может отражать другие узкие места, а не транспорт VPN.

Отчёт содержит каждый полный JSON iperf3, его итоговые показатели и доступную CPU-статистику iperf3, а также отдельные времена TCP connect и их p50/p95 в миллисекундах. Это время установки TCP-соединения, включая возможное разрешение имени, а не ICMP RTT и не задержка пакетов UDP; для сопоставимости предпочтителен числовой адрес. Запросы к latency endpoint устанавливают TCP-соединения, не отправляя данные. Отчёт содержит адреса endpoints и командные аргументы: проверяйте его перед передачей.

Ошибки и тайм-ауты сохраняются в JSON; код выхода 1 означает хотя бы один неуспешный замер или соединение, 0 — все успешны. Ошибка записи отчёта или неверные аргументы также дают ненулевой код. `--timeout` ограничивает отдельный запуск iperf3, `--connect-timeout` — каждое TCP-соединение. Для длинных тестов увеличьте `--timeout`. Инструмент не доказывает, что один протокол VPN быстрее другого: для этого нужно отдельно запустить одинаковую методику на каждом транспорте и сравнить результаты.
