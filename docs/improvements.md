## Экспериментальный Windows guard

Запускать только на отдельном стенде до проверки фильтров. Он отключён по умолчанию и не включается установщиком или треем. Адрес сервера должен быть IPv4-литералом, чтобы разрешение DNS при заблокированной сети не создавало зависимость. TLS server name проверяется независимо:

```powershell
sslim blade --profile home --host 203.0.113.10 --server-name vpn.example.com --kill-switch
# Снять только фильтры Blade после аварийного завершения, от администратора:
sslim blade unlock
```

WFP-транзакция устанавливает постоянные outbound packet filters: IPv4 разрешается через LUID Wintun, IPv6 блокируется. Исключены loopback, IPv4 endpoint сервера и broadcast для DHCP. ALE-фильтр ограничивает прямое обращение к endpoint исполняемым файлом SSLim. Это не Windows split tunneling. Изменяется только набор фиксированных GUID фильтров Blade, чужие политики не очищаются.

Фильтры сохраняются при падении процесса. При ошибке установки транзакция откатывается; уже существующие фильтры сохраняются. Штатная остановка через Ctrl+C или stop marker снимает фильтры. Закрытие соединения сервером вызывает переподключение, а не снятие защиты. При ошибке безопасного снятия используйте команду unlock и проверьте её результат.

Не заявляется защита до первого успешного включения фильтров, во время ранней загрузки Windows до BFE или при изменении политик другим администратором. Пакетные исключения и ALE-реавторизация существующих соединений требуют проверки захватом трафика. DHCP broadcast исключён на пакетном уровне; до проверки нельзя считать этот режим доказанной защитой всех исходящих пакетов.

WFP API: [условия на слоях](https://learn.microsoft.com/windows/win32/fwp/filtering-conditions-available-at-each-filtering-layer), [постоянные фильтры](https://learn.microsoft.com/windows/win32/api/fwpmtypes/ns-fwpmtypes-fwpm_filter0).

## QUIC

```powershell
sslim quic client --address 203.0.113.10:9543 --server-name vpn.example.com --secret-file client.bin --fallback-tcp-port 9443
```

QUIC v3 доступен в Linux CLI и разделяет серверный пул адресов с TCP. Обычный установщик TCP не включает UDP-порт автоматически. TLS/аутентификационные ошибки не переключаются на TCP: fallback разрешён только при таймауте QUIC handshake. После потери работающего транспорта клиент делает новую попытку. Windows Blade и Android в этой версии используют TLS/TCP.

Linux QUIC преобразует IP-пакеты в DATAGRAM с фрагментацией и ограниченным reassembly. Его накладные расходы нужно измерять отдельно от TCP.

## Проверка перед выпуском

На отдельных устройствах проверить обычный обрыв, остановку процесса, сон, смену сети и адреса endpoint, недоступность UDP, ошибки CA/SAN/ключа, активные TCP-сессии при отзыве/ротации, перезапуск Android Always-on и lockdown с исключёнными приложениями. Отдельно проверить DNS/IPv4/IPv6 packet capture, DHCP и существовавшие до включения фильтра соединения. В Linux CI выполняется `scripts/test-revocation.py`; запуск CI ещё не означает проверку Windows WFP или Android.
