# История версий

## Не выпущено

- Исправлен экспорт профилей на Windows: если пользовательский CA хранится в PEM-файле, повторно созданная ссылка снова содержит `ca=`; добавлен тест на сохранение CA при переносе.
- Удаление профиля теперь отличает отсутствующий файл от ошибки доступа/ввода-вывода; Linux-меню больше не сообщает об успешном удалении, когда файл отсутствовал.
- Android Blade сохраняет JSON-хранилище профилей через AtomicFile и восстанавливает незавершённые записи при следующем чтении, не удаляя последнюю рабочую копию.
- Установщик сервера при обновлении проверяет фактический пользовательский TCP-порт из прежнего ExecStart, а не неизменный 9443. Добавлены регрессионные проверки для `--port` и `--port=...`.

- Android Blade: при HTTP 404 от старого TCP-сервера повторяет подключение с `lab-packet/1` только после нового TLS-рукопожатия (не при тайм-ауте, ошибке сертификата или ином ответе); экспорт профиля сохраняет `u=` и `ca=`, чтобы старые подключения переносились на другой телефон.
- Исправлена двусторонняя совместимость TCP: текущий Linux-сервер снова принимает и корректно подтверждает `lab-packet/1` (клиенты v0.1.0/v0.2.0), не меняя `sync/1` (v0.3.0+), HMAC или формат пакетов. Проверка негативных сценариев (неверный ключ и неизвестный маркер) включена в CI.
- Windows Blade: не разрывает установленный VPN при ошибке необязательной проверки выходного IP через Cloudflare. Выводит диагностическую причину ошибки curl, оставляет туннель работающим; добавлены регрессионные тесты.
- TCP-клиенты: при HTTP 404 с маркером `sync/1` повторяют попытку с `lab-packet/1` для совместимости с сервером 0.2.0. TLS 1.3, HMAC и формат пакетов остаются прежними; тайм-аут TCP не запускает fallback.
- Ошибки подключения разделены по стадиям: TCP, TLS, HTTP Upgrade. Теперь тайм-аут сети не маскируется сообщением об отказе в авторизации.
- Blade: невалидный TOML-профиль больше не пропускается без предупреждения (секрет в сообщении не выводится).
- В CI добавлена интеграционная проверка актуального клиента против эмуляции TCP-сервера 0.2.0.

- Проект переименован в SSLim. Бинарник — `sslim`, Windows-клиент — подкоманда `sslim blade` (Blade), Wintun-адаптер — «Blade».
- Маркер HTTP-апгрейда на проводе заменён: `lab-packet/1` → `sync/1`; ALPN QUIC-транспорта: `govpn-lab/2` → `sslim/2`. Сервер и клиент должны быть одной версии.
- Страница репозитория обновлена, добавлен баннер `assets/banner.svg`.
- Blade: профили в `%APPDATA%\sslim\profiles` и подкоманды `import` / `list` / `show` / `remove`; поддержка ссылок `sslim://`; подключение к активному профилю с автопереконнектом (задержка 1–30 с) и ping-keepalive.
- Blade: маршруты настраивает `scripts/blade-routes.ps1` из репозитория, `-BlockIPv6` закрывает IPv6-утечку firewall-правилом на время туннеля.
- Сервер: `--secrets-file` с per-client секретами (`label:base64`); неудачная аутентификация по-прежнему выглядит как обычный 404.
- Команды `sslim keygen` (генерация секрета) и `sslim profile` (ссылка и QR для выдачи клиенту).
- Blade для Android (`android/`, версия 0.2.0, `ru.doctorbax.blade`): профили в приложении, импорт `sslim://` по клику/из буфера, редактор со всеми полями, свой CA, автопереконнект. Сборка `build.ps1` без gradle.
- Blade для Android: главный экран — только статус и кнопка-стрелка; шестерёнка в углу открывает настройки (профили, импорт, создание). При подключении — свечение вокруг стрелки, расходящиеся волны и частицы.
- CI: GitHub Actions собирает Windows-пакет (`sslim.exe` + `blade-routes.ps1` + `wintun.dll` + `install.ps1`).

## v0.2.0

- Переписаны Linux-клиент и сервер на Rust, Tokio и rustls.
- TUN читается напрямую, с повторным использованием буферов и отправкой готовых пакетов пачками.
- Сохранены формат кадров, проверка TLS-сертификата и аутентификация уровня v0.1.0. Проверен обмен между Python и Rust в обе стороны.
- Добавлены Linux x86_64 сборка, контрольная сумма, команда `probe` и проверка IPv4/IPv6 через TUN в изолированных пространствах имён.

## v0.1.0

- Первый выпуск транспорта на Python. Отправка пачек через TLS и приостановка чтения при заполнении очереди TUN.
- Локальная проверка TLS с одиночным пакетом и пачкой из 32 пакетов.
